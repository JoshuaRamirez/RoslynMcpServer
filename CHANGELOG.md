## [Unreleased]

### Changed
- `generate_overrides` now discovers and generates inherited virtual / abstract / override (non-sealed) **events**: `MemberAnalyzer.IsOverridable` / `GetOverridableMembers` include `IEventSymbol` and track already-overridden events (`IEventSymbol { IsOverride: true }`) in `alreadyOverridden`. Default / `replaceExisting: false` emits missing overridable events as `override event` stubs with empty add/remove (same body shape as `ImplementAbstractOperation.CreateEventStub` / `SyntaxGenerationHelper.CreateEventStub`). Accessibility matches the base event (not hardcoded `public` — CS0507). Intermediate concrete event overrides hide the ancestor slot (one override is emitted for the most-derived overridable event). Intermediate `new` / `new virtual` / ordinary same-name event hiders occupy the signature so a misleading `override` is not emitted for a distinct ancestor abstract/virtual slot (same spirit as `#156` for `implement_abstract`; `new virtual` remains overridable itself). `replaceExisting: true` also replaces already-overridden events on this type (match by name). `new` hiders, explicit interface event implementations, and non-override ordinary events are never replaced. Two same-name existing overrides with no exact match fail with `OverrideExists` (3152) before any write. Methods, properties, and indexers stay unchanged. `callBase` does not apply to events — empty add/remove regardless of `callBase` (abstract and virtual). `members` matches events by name; a name that is not an overridable base member / existing override still fails as today (`OverrideTargetNotFound` 2018). Preview describes generate vs replace for events and writes nothing. Additive with `replaceExisting`, `members`, `callBase`, and `preview`.
- `implement_abstract` now generates missing inherited abstract **events** on the default path: `MemberAnalyzer.GetUnimplementedAbstractMembers` includes `IEventSymbol` in the declared-set filter and the discovery switch (match by name, same as ordinary properties). A type whose only unimplemented abstract members are events succeeds (no `NoUnimplementedAbstractMembers`). Intermediate concrete event overrides still hide the inherited abstract event (same `isConcreteOverride` skip as methods/properties). Intermediate `new` / `new virtual` / ordinary same-name event hiders also occupy the signature so an `override` is not emitted for the ancestor abstract slot (that override would bind the hider and leave the abstract slot unimplemented). `new` hiders and explicit interface implementations still do not count as abstract implementations. Methods, properties, and indexers stay unchanged. `throwNotImplemented` still does not apply to events (empty add/remove via today's `CreateEventStub`). `replaceExisting` still replaces already-implemented abstract events. `members` matches events by name; a name that is not an inherited abstract member still fails as today. Preview describes the generated event and writes nothing. Additive with `replaceExisting`, `members`, and `preview`. `callBase` on `implement_abstract` remains out of scope.
- `implement_abstract` now honors `replaceExisting`: omitted / false keeps today's only-unimplemented members via `MemberAnalyzer.GetUnimplementedAbstractMembers` (plus the `IsImplementableAbstractMember` filter); when every selected member is already implemented the request still fails with `NoUnimplementedAbstractMembers` (3126) and writes nothing. `true` also treats already-implemented abstract members declared on this type as eligible (override methods / properties / indexers that implement an inherited abstract member; intermediate concrete overrides are not treated as implement_abstract targets). Omitted / empty `members` generates every missing abstract member **and** replaces every existing implementable abstract member this tool would emit. A non-empty `members` list is only those names — a name that is not an inherited abstract member still fails as today (`NoUnimplementedAbstractMembers` when the filtered set is empty). Each selected member that already has an implementation on this type is removed (including across every partial that holds it) and a standard generated stub is inserted via today's `CreateMethodStub` / `CreatePropertyStub` / `CreateIndexerStub` paths (events use an override stub with empty add/remove accessors, same body shape as `SyntaxGenerationHelper.CreateEventStub`). Match methods by name + parameter types in order + `RefKind`, properties and events by name, and indexers by the same identity forms as `MatchesRequestedMember` (metadata `Item`, `this[]`, display forms) plus parameter types and `RefKind`. Two same-name existing implementations with no exact signature match fail with `NameCollision` (3003) before any write — the flag does not guess an overload. `new` hiders, explicit interface implementations, and non-override ordinary members are never replaced. Generated stubs still honor `throwNotImplemented` (and indexer / ref-return rules). Additive with `throwNotImplemented`, `members`, and `preview`. Preview describes generate vs replace and writes nothing; when an existing member lives in another partial, preview also includes a Modify pending change for that file (implement_interface / generate_property style). Removal uses `KeepExteriorTrivia` / `KeepDirectives` so a leading `#if` / `#region` on the old member does not orphan a following `#endif` / `#endregion`. Default remains `false` so existing callers keep fail-on-already-implemented. `callBase` on `implement_abstract` is unchanged (out of scope).
- `implement_interface` now honors `replaceExisting`: omitted / false keeps today's only-unimplemented members via `MemberAnalyzer.GetUnimplementedMembers` (plus the `IsImplementableInterfaceMember` filter that skips property/event accessors); when every selected member is already implemented the request still fails with `MemberAlreadyImplemented` (3061) and writes nothing. `true` also treats already-implemented interface members declared on this type as eligible. Explicit replacements require `ExplicitInterfaceImplementations` to contain the selected interface member so `void IA.M()` is not confused with `void IB.M()`. Method type-parameter matching recurses through constructed named types / arrays / pointers / tuples / nullable wrappers so `M<T>(List<T>)` replaces instead of duplicating. Multi-variable event fields (`event Action Changed, Unrelated`) drop only the selected declarator. Omitted / empty `members` generates every missing member **and** replaces every existing implementable member this tool would emit for that interface (ordinary methods, properties, indexers, events). A non-empty `members` list is only those names — a name that is not on the interface still fails as today (`MemberAlreadyImplemented` when the filtered set is empty). Each selected member that already has an implementation on this type is removed (including across every partial that holds it) and a standard generated stub is inserted via today's `CreateMethodStub` / `CreatePropertyStub` / `CreateIndexerStub` / `CreateEventStub` paths. Match methods by name + parameter types in order + `RefKind`, properties and events by name, and indexers by the same identity forms as `MatchesRequestedMember` (metadata `Item`, `this[]`, display forms) plus parameter types and `RefKind`. When `explicitImplementation` is true, replace/match the explicit interface form; when false, the ordinary public stub. Two same-name existing implementations with no exact signature match fail with `NameCollision` (3003) before any write — the flag does not guess an overload. Generated stubs still honor `explicitImplementation` and `throwNotImplemented` (and indexer / ref-return rules). Property/event accessors (`get_Item` / `set_Item` / `add_` / `remove_`) are never emitted as ordinary methods. Additive with `explicitImplementation`, `throwNotImplemented`, `members`, and `preview`. Preview describes generate vs replace and writes nothing; when an existing member lives in another partial, preview also includes a Modify pending change for that file (generate_property / constructor style). Removal uses `KeepExteriorTrivia` / `KeepDirectives` so a leading `#if` / `#region` on the old member does not orphan a following `#endif` / `#endregion`. Default remains `false` so existing callers keep fail-on-already-implemented. `implement_abstract` `replaceExisting` and `callBase` on `implement_interface` are unchanged.
- `implement_interface` now routes missing interface **indexers** (`IPropertySymbol.IsIndexer`) through `SyntaxGenerationHelper.CreateIndexerStub` so they emit `this[...]` indexer declarations (bracketed parameter list) instead of a property named `this[]`. Ordinary properties stay on `CreatePropertyStub`. Methods and events stay on `CreateMethodStub` / `CreateEventStub`. `callBase` stays the default `false` (interface members have no `base` to call). Implicit interface stubs are `public` without `override` (interface members are abstract, but `override` is CS0115 — the shared helper skips `override` when the member's containing type is an interface; abstract-class / virtual / override members used by `implement_abstract` / `generate_overrides` still get `override`). `ref` / `ref readonly` interface indexers keep that return kind; getters still throw when `throwNotImplemented` is false (`return default` is not a valid ref return). Accessors still honor `throwNotImplemented` for ordinary indexers (true → throw bodies; false → default-return getter / empty setter), including explicit implementations. `explicitImplementation`, `members`, and `preview` stay additive; `members` still matches indexer metadata name (`Item`), Roslyn name (`this[]`), and conventional display (`this[int i]`). Preview lists members and writes nothing. Accessor methods (`get_Item` / `set_Item`) are not emitted as ordinary methods.
- `generate_overrides` now honors `callBase` on **properties and indexers**: omitted / true (the existing default) emits `return base.Prop;` / `base.Prop = value;` for non-abstract virtual/override properties, and `return base[i];` / `base[i] = value;` for indexers (same parameter names / `RefKind`); abstract properties still `throw new NotImplementedException();` in accessors (no legal `base` implementation). `false` keeps today's property/indexer stub bodies (default-return getter / empty setter for virtuals). Ordinary method `callBase` is unchanged (`base.M(...)` when true and non-abstract). Additive with `replaceExisting`, `members`, and `preview`. Preview describes that property accessors will (or will not) call `base` (a mixed abstract + virtual selection with `callBase` true qualifies as non-abstract accessors only), and writes nothing. Default remains `true`. `implement_interface` / `implement_abstract` / other generate_* tools are unchanged.
- `generate_method_stub` now honors `replaceExisting`: omitted / false keeps today's fail-on-clash (`NameCollision` 3003) when a compatible ordinary method already exists on the target type (same name, type-parameter arity, parameter count, and parameter types in order via `ValidateNoCompatibleMethod` / `ParameterTypeMatches`); `true` removes that method declaration (including across every partial that holds it) and inserts a freshly generated stub. Body still follows `throwNotImplemented`, `generateAsync`, visibility, and return type. `RefKind` is also matched when the stub can infer it so `ref` / `out` / `in` overloads are not wrongly replaced. Constructors, operators, local functions, explicit interface implementations, accessors, and other non-ordinary methods are never replaced. Two compatible ordinary methods with no single exact target fail with `NameCollision` before any write — the flag does not guess an overload. When no compatible method exists, generation proceeds as today. Additive with `methodName`, `returnType`, `visibility`, `generateAsync`, `throwNotImplemented`, and `preview`. Default remains `false` so existing callers keep fail-on-clash. Preview describes generate vs replace and writes nothing; when the existing method lives in another partial, preview also includes a Modify pending change for that file (generate_property-style). Removal uses `KeepExteriorTrivia` / `KeepDirectives` so a leading `#if` / `#region` on the old method does not orphan a following `#endif` / `#endregion`. Other generate_* / implement_* tools are unchanged.
- `generate_method_stub` now honors `throwNotImplemented`: omitted / true keeps today's `throw new global::System.NotImplementedException();` stub; `false` uses `SyntaxGenerationHelper.CreateDefaultReturnBody` (empty block for `void`; `return null;` for reference types; `return default(T);` for value types / type parameters). Async `Task` / `Task<T>` stubs (from `generateAsync` or an awaited call site) unwrap the task type so a non-throwing body still compiles — empty block for `async Task`, default-return of the inner type for `async Task<T>` (never `return null;` inside `async Task`; no dummy storage). `ref` / `ref readonly` returns still throw even when the flag is false (`return default` is not a valid ref return). `methodName`, `returnType`, `visibility`, `generateAsync`, and `preview` stay additive. Preview describes throwing vs non-throwing and writes nothing. Default remains `true` so existing callers keep throw stubs. `implement_interface` and `implement_abstract` are unchanged.
- `generate_property` now honors `replaceExisting`: omitted / false keeps today's fail-on-clash (`NameCollision` 3003) when any non-implicit member with the target property name already exists on the type; `true` removes the existing property declaration(s) that match that name (including across every partial that holds one) and inserts a freshly generated property. Auto / init-only / backing-field form still follows `propertyName`, `propertyType`, `fieldName`, `visibility`, and `initOnly`. Fields and methods of the same name are never removed and still fail with `NameCollision`. Two same-named properties (for example a public property plus an explicit interface property) fail with `NameCollision` before any write — the flag does not guess. Name matching scans all members (not only `GetMembers(name)`) so explicit-interface properties whose metadata name is `IFoo.Name` still count. Record / primary-constructor properties with no `PropertyDeclarationSyntax` are not replaced (`NameCollision`, same spirit as constructor never replacing a primary constructor). When no matching property exists, generation proceeds as today. Additive with existing params. Default remains `false` so existing callers keep fail-on-clash. Preview describes generate vs replace and writes nothing; when the existing property lives in another partial, preview also includes a Modify pending change for that file (constructor-style). Removal uses `KeepExteriorTrivia` / `KeepDirectives` so a leading `#if` / `#region` on the old property does not orphan a following `#endif` / `#endregion`.
- `implement_abstract` now honors `throwNotImplemented`: omitted / true keeps today's `throw new global::System.NotImplementedException();` stubs for methods, property accessors, and indexer accessors; `false` uses `SyntaxGenerationHelper.CreateDefaultReturnBody` for methods and getters (empty block for `void`; `return null;` / `return default(T);` otherwise) and empty blocks for setters / init setters — same body shape as `implement_interface` when throw is false. `ref` / `ref readonly` methods and getters still throw even when the flag is false (`return default` is not a valid ref return; no dummy storage is invented). Override modifiers, accessibility, required, init-only, type parameters, `members`, and `preview` stay unchanged. Preview describes throwing vs non-throwing stubs and writes nothing. Default remains `true` so existing callers keep throw stubs. `implement_interface` is unchanged.
- `generate_tostring` now honors `callSuper`: omitted / false keeps today's member-only ToString (no `base.ToString()`); `true` folds the immediate base type's parameterless instance `ToString` into the generated override — `{base.ToString()}` first in an interpolated body (before this type's member interpolations), and `sb.Append(base.ToString())` first on the StringBuilder path (before this type's member Appends). Rejected when the immediate base is `System.Object` or `System.ValueType` (`CallSuperOnObjectBase` 3146), or when the immediate base's parameterless instance `ToString()` is abstract (`CallSuperOnAbstractBase` 3147). Zero collected members is allowed when `callSuper` is true (base-only ToString; skips `NoMembersToGenerate` 3055). Distinct from `includeInheritedMembers` (base-method fold-in vs member collection); combining both is allowed. Additive with `fields`, `includeProperties`, `format`, `includeInheritedMembers`, `replaceExisting`, and `preview`. Preview describes that base ToString will be included and writes nothing. `generate_equals_hashcode` `callSuper` is unchanged.
- `generate_overrides` now honors `replaceExisting`: omitted / false keeps today's skip of members this type already overrides (`GetOverridableMembers` plus Object `ToString` / `Equals(object)` / `GetHashCode`); a named member that is already overridden still fails with `OverrideTargetNotFound` (2018) before any write. `true` makes those already-overridden members eligible alongside missing overridable members. Omitted / empty `members` generates missing overrides **and** replaces every existing override this tool would have emitted (overridable base virtual/abstract methods and properties, plus Object `ToString` / `Equals(object)` / `GetHashCode`). A non-empty `members` list is only those names — a name that is neither an overridable base member nor an existing override still fails with `OverrideTargetNotFound` before any write. Each selected member that already has an override on this type is removed (method or property, including across every partial that holds it) and a standard generated override is inserted. Match methods by name + parameter types in order + `RefKind`, and properties by name. Two existing overrides that share a name with no exact signature match fail with `OverrideExists` (3152) before any write — the flag does not guess an overload. Generated bodies still honor `callBase` (`true` / default emits `base.M(...)` for non-abstract virtuals; abstract members still `throw new NotImplementedException();`; `false` keeps today's no-`base` stub). `new` hiders, explicit interface implementations, non-override methods of the same name, and primary constructors are never replaced. Extra modifiers on the old override (`sealed`, `async`, attributes) are not copied. The regenerated override keeps the inherited accessibility from the base target (`protected` / `protected internal` / `private protected` / `internal`, not a hardcoded `public` — CS0507) and each parameter's `RefKind` on the declaration and on `base.M(...)` (`ref` / `out` / `in` / `ref readonly`). Preview describes which overrides will be generated vs replaced, and writes nothing.
- `generate_constructor` `callBase` now also applies to **record classes** (non-copy): omitted / false keeps today's record non-copy shape (no `: base(...)`). When `true` without `copyConstructor` and the target is a record class (not a record struct / struct / ordinary class) whose immediate base is a class or record other than `object` / `ValueType`, the same prefix-matching rules as ordinary-class `callBase` apply: accessible instance constructors (public / protected / protected-internal, plus internal / private-protected when the same assembly) whose parameter types in order (by-value, same `RefKind`) are a prefix of the generated constructor are candidates; longest prefix wins, then case-insensitive parameter-name matches; a remaining tie is `AmbiguousBaseConstructor` (3151). A match of length `k >= 1` emits `: base(p1, ..., pk)` and does not reassign those members; only an accessible parameterless match emits `: base()` without skipping body members; `addNullChecks` still guards forwarded non-nullable reference / `Nullable<T>` parameters. Preview describes whether a `: base(...)` initializer was added (and which base constructor), and writes nothing. Primary constructors are still never replaced.
- `generate_constructor` now honors `callBase`: omitted / false keeps today's ordinary-class non-copy shape (no `: base(...)`). Record copy constructors and `classBaseCopy` stay unchanged. `true` with `copyConstructor` is rejected with `CallBaseConflictsWithCopyConstructor` (3149) before any generate, replace, or preview write. When `true` without `copyConstructor` and the target is an ordinary class (not a record / struct / record struct) whose immediate base is a class other than `object`, accessible instance constructors on that base (public / protected / protected-internal, plus internal / private-protected when the same assembly) are candidates: a base constructor whose parameter types in order (by-value, same `RefKind`) are a prefix of the generated constructor's parameter types is selected, preferring the longest prefix, then case-insensitive parameter-name matches; a remaining tie is rejected with `AmbiguousBaseConstructor` (3151) before any write. A match of length `k >= 1` emits `: base(p1, ..., pk)` using the generated constructor's first `k` parameter identifiers and does not reassign the members that produced those parameters; `addNullChecks` still emits `ArgumentNullException` guards for those forwarded parameters in the derived body before assignments. - `generate_constructor` now honors `classBaseCopy`: omitted / false keeps today's class copy-constructor shape (no `: base(...)` on ordinary classes). When both flags are true and the target is an ordinary class (not a record / struct / record struct) whose immediate base is a class other than `object` with an accessible instance constructor of exactly one by-value parameter of the **base** type, the generated copy constructor emits `: base((Base)<copyParameter>)` (argument cast to the immediate base type) so `Derived(Derived other) : base((Base)other)` binds to that `Base(Base)` constructor even when `Base(IFoo)` or a more-specific inaccessible `Base(Derived)` would otherwise win. Records, record structs, and structs ignore the flag. Additive with `visibility`, `replaceExisting`, `includeProperties`, `includeInheritedMembers`, `members`, `addNullChecks`, and `preview`. - `generate_constructor` now honors `copyConstructor`: omitted / false keeps today's one-parameter-per-member constructor; `true` generates a single-parameter constructor whose parameter type is the target type and whose body assigns each selected member from that parameter (`this.Name = other.Name;`).
